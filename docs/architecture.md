# Architecture

This document describes how `strata-qemu-testing` works as it exists in
this repository today. It is a map of the code, not a proposal. For
operator instructions see the [README](../README.md).

## Purpose

Boot real Linux desktop sessions (compositor, autologin, session D-Bus)
under QEMU/KVM so that Strata's `install.sh` and the installed application
can be exercised against several distributions. Every run uses a throwaway
qcow2 overlay on top of a reproducible "golden" image built from a
committed recipe.

The host side is a stdlib-only Python package (`strataqemu`). SSH is
OpenSSH via `subprocess`; QEMU control is QMP and the QEMU guest agent
over Unix sockets; screenshots come from in-guest tools with a
stdlib RFB (VNC) client as fallback.

## Operator surface

`mise.toml` defines the tasks; each forwards raw argv to
`python -m strataqemu <command>`. Tasks that spawn QEMU are
`interactive = true`. `run-test`, `vm-run`, and `vm-live` depend only on `check-host`;
nothing builds a golden implicitly.

| Task | Command | What it does |
| --- | --- | --- |
| `check-host` | `check-host` | Host capability check. Generates the SSH key on first success. |
| `image-build` | `image-build [--force] <guest>` | Build or reuse a golden. Prints the golden path. |
| `run-test` | `run-test <guest> (--session-only \| --install-from release \| --install-from local-archive PATH \| --omarchy-bindings \| --update-from VERSION \| --udiskie-unlock \| --luks-hotplug PATH) [--keep]` | Boot an overlay and run smokes. |
| `vm-run` | `vm-run [--graphical] [--keep] <guest>` | Interactive throwaway overlay. |
| `vm-live` | `vm-live (--from-tag VERSION \| --from-local PATH) [--graphical] [--headless] [--keep] <guest>` | Interactive overlay with Strata installed and `~/fixtures` sample files. |
| `image-prune` | `image-prune [--images]` | Delete run dirs; with `--images` also goldens. Never `keys/`. |
| `test` | `python -m unittest discover -s tests -t .` | Host unit tests. |
| `spike-wayland-ubuntu` (hidden) | `spike-wayland-ubuntu [--keep]` | Ad-hoc Noble session spike; predates the recipe system. |

`-v/--verbose` enables debug logging on stderr. A lone `--` anywhere in
argv is dropped so `mise run run-test -- ubuntu-2404 --session-only` works.

## Cache

Root: `$STRATA_QEMU_CACHE`, else `$XDG_CACHE_HOME/strata-qemu-testing`,
else `~/.cache/strata-qemu-testing`.

```
$CACHE/keys/id_ed25519(.pub)          generated by check-host
$CACHE/downloads/<source file>        pinned cloud image or ISO
$CACHE/images/<id>-<digest>.qcow2     golden (read-only, 0444)
$CACHE/images/<id>.qcow2              symlink to the current golden
$CACHE/images/<id>.vars.fd            post-install OVMF vars (ISO autoinstall guests only)
$CACHE/images/<id>.json               provenance
$CACHE/runs/<UTC stamp>-<id>-build/   image-build working dir (deleted on success)
$CACHE/runs/<UTC stamp>-<id>/         run-test run dir
$CACHE/runs/<UTC stamp>-<id>-vm/      vm-run run dir (deleted on success unless --keep)
$CACHE/runs/<UTC stamp>-<id>-live/    vm-live run dir (deleted on success unless --keep)
```

Per-run files (`artifacts.RunArtifacts`): `overlay.qcow2`, `OVMF_VARS.fd`,
`serial.log`, `qemu.log`, `ssh.log`, `qmp.sock`, `qga.sock`, `ssh_port`,
`result.json`, `screenshot.png`, `qmp-session.png`, and on build timeouts
`timeout.png` / `qmp-timeout.png`. `throwaway_paths()` is the set deleted
after a successful `run-test`: overlay, vars copy, and the two sockets.

## Host check (`cli.check_host`)

Fail-closed. All findings are collected and printed; any one fails the
command. Checks, in order:

1. Not running as root.
2. `/dev/kvm` exists and is readable and writable.
3. Binaries on `PATH`: `qemu-system-x86_64`, `qemu-img`, `xorriso`,
   `mkfs.vfat`, `mcopy`, `ssh`, `curl`.
4. virgl: `libvirglrenderer.so*` under `/usr/lib`, `/usr/lib64`, or
   `/usr/lib/*`, plus a `/dev/dri/renderD*` node.
5. OVMF code: first existing 4M, non-secboot file among
   `edk2/x64/OVMF_CODE.4m.fd`, `OVMF/OVMF_CODE_4M.fd`,
   `edk2/ovmf/OVMF_CODE.fd` under `/usr/share`.
6. `MemAvailable` from `/proc/meminfo` is at least 9 GiB.

On success it generates `$CACHE/keys/id_ed25519` with `ssh-keygen -t
ed25519 -N ""` if missing, and returns the OVMF path and key path for the
callers (`image-build`, `run-test`, `vm-run`, `vm-live`, spike).

The check is injectable (`CheckHostEnv`) so unit tests never probe the
real machine.

## Guest recipes (`guest.py`)

A guest is a directory `images/<id>/` containing `image.toml`,
`bootstrap.sh`, `setup.sh`, and either `user-data.yaml.tmpl`
(`source_kind = "cloud-image"`) or a `cidata/` directory
(`source_kind = "iso-autoinstall"`).

`image.toml` fields:

| Key | Notes |
| --- | --- |
| `id` | Must equal the directory name. No `.` or path separators. |
| `arch` | Recorded; only `x86_64` recipes exist. |
| `firmware` | `uefi` or `bios`. |
| `source_kind` | `cloud-image` or `iso-autoinstall`. |
| `source_url` | Must not contain `/current/` or `/latest/`. |
| `source_sha256` | 64 hex chars. Required. |
| `source_filename` | Required when `source_url` is a directory (Fedora scrape). |
| `disk_gb`, `memory_mib`, `cpus` | Working/overlay disk size and QEMU `-m`/`-smp`. |
| `build_timeout_s` | Budget for `setup.sh`, and for ISO autoinstall to reach SSH. |
| `boot_timeout_s` | Budget for SSH to answer after QEMU starts. |
| `ovmf_code`, `ovmf_vars_template` | Parsed and stored; firmware paths actually come from the host search order. |
| `[session]` | `kind`, `display_manager`, `compositor`, `autologin`, `wayland`. |
| `[packages]` | `manager`, optional `snapshot_url`, `runtime` list. |
| `[user]` | `name`, `groups`. |
| `[cidata]` | ISO autoinstall only: `disk` must be `/dev/vda`, `encrypt` must be `false`. |

Digests:

- `recipe_digest` = SHA-256 over `image.toml`, `bootstrap.sh`, `setup.sh`,
  the optional drop-ins (`greetd-config.toml`, `hyprland.lua`,
  `hyprland.conf`, `skip-wizard.sh`), every `*.tmpl` under the recipe
  directory, and everything under `cidata/`. Each file contributes its
  relative path, length, and bytes.
- `golden_digest` = SHA-256 of `recipe_digest:source_sha256`.

The golden filename is `<id>-<golden_digest>.qcow2`, so editing any covered
recipe file or re-pinning the source produces a new golden and
`image-build` rebuilds.

### Guests in tree

| Guest | Source | Firmware | Display manager / compositor | Notes |
| --- | --- | --- | --- | --- |
| `arch` | arch-boxes dated cloudimg | BIOS | greetd / Hyprland | pacman pinned to the matching `archive.archlinux.org` day; `hyprland.lua` config |
| `ubuntu-2404` | dated Noble cloudimg | UEFI | GDM / GNOME Shell | APT pinned to `snapshot.ubuntu.com`; initial-setup and tour masked |
| `fedora-workstation` | F44 Cloud Base (directory scrape + CHECKSUM sidecar) | UEFI | GDM / GNOME Shell | Workstation environment installed by `dnf`; firewalld opens SSH |
| `omarchy-4` | official 4.x ISO | UEFI | SDDM / Hyprland | archinstall autoinstall from CIDATA |
| `omarchy-3` | official 3.x ISO | UEFI | SDDM or `omarchy-seamless-login` / Hyprland | ISO has no CIDATA loader; `skip-wizard.sh` is pushed over qemu-ga |

All guests create user `tester` (password `foobar`) with the generated SSH
public key and, after `setup.sh`, passwordless sudo, lingering, autologin
into a Wayland session, and `qemu-guest-agent`. Each `setup.sh` leaves
`/var/tmp/strata-inventory.txt`, `strata-glibc.txt`, and `strata-gtk.txt`
(Omarchy also `strata-omarchy-version.txt`) for provenance.

## QEMU argv (`qemu.build_qemu_argv`)

One builder produces every argv. Fixed parts:

```
-machine q35,accel=kvm,usb=off -cpu host -smp <cpus> -m <memory_mib> -vga none
-drive file=<disk>,if=none,id=drive0,discard=unmap,cache=<mode>
-device virtio-blk-pci,drive=drive0,bootindex=1[,addr=0x8]
-netdev user,id=net0,hostfwd=tcp:127.0.0.1:<ssh_port>-:22 -device virtio-net-pci,netdev=net0
-serial file:<run>/serial.log
-qmp unix:<run>/qmp.sock,server,wait=off
-chardev socket,path=<run>/qga.sock,server=on,wait=off,id=qga
-device virtio-serial-pci -device virtserialport,chardev=qga,name=org.qemu.guest_agent.0
-usb -device usb-tablet
```

Variants:

- Headless (image-build, run-test, vm-run default, `vm-live --headless`):
  `-device virtio-gpu-gl-pci -display egl-headless,gl=on -vnc 127.0.0.1:<display>`.
- Graphical (`vm-run --graphical`, `vm-live` default): `-device virtio-vga-gl -display gtk,gl=on`
  (or `sdl` when QEMU's `-display help` lacks gtk). No VNC.
- UEFI: two `if=pflash` drives, code read-only, vars a per-run copy.
- Cloud-init seed: `virtio-scsi-pci` + `scsi-cd` with the NoCloud ISO.
- ISO autoinstall: `ide-cd` with the install ISO at `bootindex=2`, and the
  CIDATA VFAT as a second `virtio-blk-pci` at PCI `addr=0x9`. `drive0` is
  pinned at `addr=0x8` so the target disk stays `/dev/vda`.

Disk cache is `writeback` for image-build working disks and `unsafe` for
throwaway overlays.

### Ports (`ports.py`)

SSH forward and VNC display are allocated by binding `127.0.0.1:0` and
releasing. Fallback ranges are 22022-22999 (SSH) and 5900-5999 (VNC
display, which QEMU maps to TCP 5900+display). If QEMU exits immediately
with "address already in use" the whole allocation is retried up to five
times. Nothing ever binds a non-loopback address.

### Guest control

- **QMP** (`_qmp_execute`): greeting, `qmp_capabilities`, one command.
  Used for `system_powerdown` and best-effort `screendump`.
- **qemu-ga** (`qga_execute`, `qga_guest_exec`, `qga_guest_file_write`,
  `qga_guest_shutdown`): no handshake. `guest-exec` runs
  `/usr/bin/bash -lc <cmd>` and polls `guest-exec-status`. File writes are
  chunked base64 over one connection.
- **VNC** (`vnc_framebuffer_png`): RFB 3.8, no auth, raw encoding, one
  full framebuffer update written as an 8-bit RGB PNG. Used as the
  screenshot fallback and for timeout evidence.
- **Shutdown cascade** (`Machine.shutdown`): qemu-ga `guest-shutdown`,
  then `ssh sudo systemctl poweroff`, then QMP `system_powerdown`, then
  `kill()`. The first transport that reports success stops the cascade;
  callers then wait on the process and kill if it does not exit.

## Image build (`image_build.build_live`)

`run_image_build`:

1. Load the recipe. If `$CACHE/images/<id>-<digest>.qcow2` exists and
   `--force` is not set, print its path and exit 0 without running
   `check-host`.
2. Run `check-host`; abort on failure.
3. Print a one-line duration expectation to stderr and call `build_live`.

`build_live`:

1. Assert free space on the cache filesystem:
   `2 * disk_gb + 10 GiB + source size` (source assumed 1 GiB if not yet
   downloaded). Re-checked after download.
2. Create `$CACHE/runs/<stamp>-<id>-build/`.
3. Run `bootstrap.sh` with `STRATA_QEMU_CACHE`, `SOURCE_URL`,
   `SOURCE_SHA256`, `SOURCE_FILENAME` in the environment. The script must
   leave `$CACHE/downloads/<SOURCE_FILENAME>` with the pinned SHA-256.
4. Prepare the working disk:
   - cloud-image: `qemu-img convert -O qcow2` then `qemu-img resize` to
     `disk_gb`.
   - iso-autoinstall: `qemu-img create -f qcow2` blank disk of `disk_gb`.
5. Render the seed:
   - cloud-image: `user-data.yaml.tmpl` with `{{SSH_AUTHORIZED_KEY}}`
     replaced, plus `meta-data` (`instance-id` and `local-hostname` =
     guest id), packed with `xorriso -as mkisofs -V cidata`. The rendered
     text is scanned for credential-like tokens (GitHub, Tailscale) and
     the build fails if any appear.
   - iso-autoinstall: `cidata/user_configuration.json` (validated:
     `default_layout` on `/dev/vda`, 1 MiB-aligned partitions, no
     `disk_encryption`, Limine bootloader schema for 3.x or
     `bootloader_config` + `omarchy_install.mode = full_disk` for 4.x),
     `user_credentials.json.tmpl` (must list `tester` and a `$6$` root
     hash), `user_encrypt_installation.txt` (must be `false`), and
     `authorized_keys.tmpl`. Written into a 4 MiB VFAT labeled `CIDATA`
     with `mkfs.vfat` and `mcopy`.
6. UEFI guests: copy the host `OVMF_VARS` template into the run dir.
7. Spawn QEMU (headless argv, `cache=writeback`). QEMU stdout/stderr go to
   `qemu.log`. An immediate exit is reported with the log tail.
8. Wait for the guest:
   - cloud-image: `wait_ssh` until `ssh tester@127.0.0.1 true` succeeds
     (budget `boot_timeout_s`; 30 consecutive pubkey rejections abort with
     an `authorized_keys` hint), then `cloud-init status --wait` (600 s).
   - omarchy-3 only: `wait_qga` (300 s), write `skip-wizard.sh` to
     `/root/` over qemu-ga and execute it. The script copies the CIDATA
     files into `/root`, stubs the gum configurator, patches
     `authorized_keys` + `sshd` into archinstall's automated script,
     patches the post-install "Reboot Now" prompt, and kills tty1 so the
     automated path respawns.
   - iso-autoinstall: `wait_iso_autoinstall` until SSH accepts `tester`
     and `omarchy version` reports the expected major (budget
     `build_timeout_s`). Pubkey rejections are expected while the live ISO
     is installing; qcow2 growth past 1 MiB is logged once as progress.
9. `scp` `setup.sh` and any drop-ins (`greetd-config.toml`,
   `hyprland.lua`, `hyprland.conf`) to `/tmp/`, then run
   `SNAPSHOT_URL=... sudo -n bash /tmp/setup.sh` (cloud-image) or
   `printf foobar | sudo -S -p '' bash /tmp/setup.sh` (ISO autoinstall,
   which only has password sudo until `setup.sh` writes NOPASSWD). Budget
   `build_timeout_s`. Every SSH command and its output is appended to
   `ssh.log`.
10. `scp` back the inventory files into `<run>/inventory/`.
11. Shut down via the cascade; wait up to 60 s, then kill.
12. Move `working.qcow2` to the golden path, `chmod 0444`, update the
    `<id>.qcow2` symlink, copy the vars file to `<id>.vars.fd` for UEFI
    ISO guests, write `<id>.json` provenance (source URL/SHA/filename,
    recipe and golden digests, build stamp, package inventory, glibc and
    GTK versions, Omarchy version where applicable), and delete the run
    dir.

On any exception the machine is shut down or killed, the run dir is kept,
the traceback is logged, and `image-build` exits 1. Ctrl-C also shuts the
machine down and exits 130. Timeouts inside the wait loops capture
`timeout.png` (VNC) and `qmp-timeout.png` (QMP) before raising.

## run-test (`run_test.run_run_test`)

Argument validation happens before anything touches the cache:

- Exactly one of `--session-only`, `--install-from`, `--omarchy-bindings`,
  `--update-from VERSION`, `--udiskie-unlock`, or `--luks-hotplug PATH`
  is required.
- `--omarchy-bindings` is Omarchy-only (`omarchy-3`, `omarchy-4`) and
  cannot be combined with the other flows.
- `--udiskie-unlock` is Omarchy/Arch (`omarchy-3`, `omarchy-4`, `arch`) and
  cannot be combined with the other flows. It sources installer helpers
  with PATH/`BIN_PATH` isolated; it does not spawn real udiskie.
- `--luks-hotplug PATH` is Omarchy/Arch and cannot be combined with the
  other flows. PATH is a host binary, tarball, or checkout and must
  exist. It installs that Strata, registers the udiskie handler,
  hotplugs a LUKS virtio-blk disk, and asserts Strata is called. Host
  `qemu-img` and `cryptsetup` format the throwaway image.
- `--update-from` is exclusive with the other flows. VERSION is a previous
  release tag (`0.15.0` or `v0.15.0`). The default previous-version list is
  `0.15.0,0.14.0`; override with `STRATA_QEMU_UPDATE_FROM`.
- `--install-from local-archive` requires an existing host path;
  `--install-from release` refuses a path.
- `--omarchy-bindings` optionally uploads `STRATA_QEMU_INSTALL_SH`
  instead of curling `lgse/strata` `main`; a missing path fails closed.
- `--udiskie-unlock` uploads `STRATA_QEMU_INSTALL_SH` when set (missing
  path fails closed) or the committed helper fixture otherwise.
- A missing golden fails with `run \`mise run image-build -- <id>\` first`
  and never builds one. This check runs before `check-host`.

Then:

1. `check-host`.
2. Create `$CACHE/runs/<stamp>-<id>/` and an overlay:
   `qemu-img create -f qcow2 -F qcow2 -o backing_file_strict=on -b <abs golden>`
   (retried without `backing_file_strict` if this `qemu-img` rejects it).
   UEFI guests get a fresh copy of `<id>.vars.fd` if it exists, else the
   host template.
3. Spawn QEMU (headless argv, `cache=unsafe`), `wait_ssh` for
   `boot_timeout_s`.
4. Run steps (see below). Each step records `name`, `status`, `seconds`,
   and step-specific fields into `result.json`.
5. On success print `run-test: session ok (<id>)`, `run-test: ok (<id>)`,
   `run-test: update-from VERSION ok (<id>)`,
   `run-test: omarchy-bindings ok (<id>)`,
   `run-test: udiskie-unlock ok (<id>)`, or
   `run-test: luks-hotplug ok (<id>)` and the screenshot path, shut
   down, delete the overlay, vars copy, and sockets (unless `--keep`), and
   print `run dir: <path>`. Logs, `result.json`, and screenshots stay.
6. On failure record `error` and the recorded guest commands in
   `result.json`, keep the whole run dir, print `kept run dir: <path>`,
   exit 1. Ctrl-C exits 130.

### Steps (`tests_spec.py`)

**session**: upload `guest-tests/smoke-session.sh` and run it with
`SMOKE_COMPOSITOR=<gnome-shell|Hyprland>` every 2 s for up to 60 s. The
script picks the `Type=wayland Class=user State=active Seat=seat0` logind
session for the user (never the SSH session; `Type=x11` is an immediate
failure), checks the user bus with `busctl --user status`, finds the first
`wayland-*` socket in `/run/user/<uid>`, exports the newest Hyprland
instance signature if `hypr/` exists, and asserts the compositor process
is running. It prints `KEY=value` lines; the host parses
`SESSION_ID`, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS`,
`WAYLAND_DISPLAY`, `HYPRLAND_INSTANCE_SIGNATURE` and prefixes them onto
later guest commands.

**screenshot** (session-only): `grim` on Hyprland, `gnome-screenshot -f`
on GNOME. A missing binary fails with "screenshot tool missing; rebuild
the golden". If `gnome-screenshot` times out or does not produce a PNG,
the host grabs the VNC framebuffer instead. A QMP `screendump` is also
attempted into `qmp-session.png` and ignored on failure. After the run,
every recorded guest command is checked against a forbidden list
(`install.sh`, `strata --version`, `gtk-launch`, `gio launch`,
`NameHasOwner`, the bus name) so `--session-only` cannot silently grow
into an install test.

**install** (`--install-from`): resolve the intended version (from the
archive filename for `local-archive`, from GitHub `/releases/latest` for
`release`). Upload `guest-tests/smoke-install.sh` (and the archive to
`/tmp/strata-archive.tar.gz` for `local-archive`). The script downloads
`install.sh` from `lgse/strata` `main`, prints `INSTALL_SH_SHA256=`, runs
it with `--non-interactive --with-desktop-entry --without-file-chooser`
(plus `--archive PATH` when given), and asserts `~/.local/bin/strata` is
executable. On `arch` it first fails if any Omarchy installation is
present. Budget 180 s.

**version**: run `~/.local/bin/strata --version` with a 10 s timeout. If
the first line looks like a version, it must equal the intended version.
If the command times out or does not print a version, the step is recorded
as `skip` with reason "strata --version is not a CLI". The About page
screenshot (`about-version`) is the visual fallback in that case.

**desktop-entry**: `~/.local/share/applications/io.github.lgse.Strata.desktop`
exists and its `Exec=` points at `~/.local/bin/strata`.

**window**: launch via `gtk-launch io.github.lgse.Strata` (or
`gio launch`) in the session environment, then poll for up to 45 s:
`hyprctl clients -j` containing class `io.github.lgse.Strata` on
Hyprland, or `gdbus ... NameHasOwner io.github.lgse.Strata` on GNOME. A
screenshot is taken whether or not the window appeared; the step then
fails if the oracle timed out.

**about-version**: when `version` skipped, drive Settings → About and
screenshot `about-version.png`. Ctrl+, opens Settings (General is
focused after the first Tab). Four more Tabs reach About; Space
activates it. Input: in-guest `wtype` (full sequence), else Hyprland
`hyprctl` for Ctrl+, plus QMP Tab×5+Space, else the whole sequence via
QMP. Skipped with "CLI version already recorded" when `--version`
worked, or when no input path succeeded.

On `--update-from`, About is captured twice: `about-version-before.png`
on the seeded previous install (then Strata is quit so the binary can
be replaced) and `about-version-after.png` after the latest install.

`result.json` for install runs also records `install_method`,
`install_sh_sha256`, `intended_version`, `observed_version` (when the
version step passed), `about_version` (path, when the About screenshot
passed), and `archive_sha256` (for `local-archive`).

`--install-from` on Omarchy guests is the same sequence as on
GNOME/Arch. It does not run Omarchy detection or rewrite Hyprland
bindings.

**update-from** (`--update-from VERSION`): same guests as `--install-from`.
Resolve latest from GitHub `/releases/latest` (or an injected intended
version). Fail closed if VERSION equals latest. Upload
`guest-tests/smoke-update.sh`. Steps: session → install-previous (download
the GitHub archive for VERSION, or a host-uploaded tarball, extract, install
the binary and desktop entry) → version-previous (`strata --version` must
match VERSION) → update (move the previous binary aside because
`install.sh --non-interactive` refuses an existing `~/.local/bin/strata`,
then run current `install.sh` with the same flags as `--install-from`) →
about-version-before → update → version (must match latest) →
desktop-entry → window → about-version-after.

`result.json` for this flow records `from_version`, `intended_version`,
`observed_previous_version` (when the previous version step passed),
`observed_version` (when the latest version step passed), and
`install_sh_sha256`. The default VERSION list is
`DEFAULT_UPDATE_FROM_VERSIONS` (`0.15.0`, `0.14.0`); override with
`STRATA_QEMU_UPDATE_FROM`.

**omarchy-detect** (`--omarchy-bindings`): upload
`guest-tests/smoke-omarchy-detect.sh` and a staged `install.sh`. The
script sources the installer under `STRATA_INSTALLER_TESTING=1` and
prints `DETECTED_MAJOR=`. The host checks the live major against the
guest (4 or 3), then probes `omarchy_major_from` on the `#743` token
matrix and `detect_omarchy_major` against a fake `omarchy version` of
`dev (b280f130)` (must fall back to the version file, not hash-match 3).

**omarchy-bindings** (`--omarchy-bindings`): upload
`guest-tests/smoke-omarchy-bindings.sh`, source `configure_omarchy_bindings`
for the detected major, and assert `bindings.lua` (4) or `bindings.conf`
(3) carries the installer marker while the unused sibling does not. Then
the same in-guest screenshot as session-only.

`result.json` for this flow records `omarchy_major`, `omarchy_bindings`
(`lua` or `conf`), and `omarchy_pr743_probes`.

**udiskie-unlock** (`--udiskie-unlock`): upload
`guest-tests/smoke-udiskie-unlock.sh` and a staged `install.sh` (fixture
or `STRATA_QEMU_INSTALL_SH`). The script sources
`configure_udiskie_unlock` / `parse_args` under
`STRATA_INSTALLER_TESTING=1` with PATH limited to a stub directory,
`BIN_PATH` recording argv only, and a temp archive marker. The host
checks a short in-guest case list (flag parse, eligible prompt yes/no,
Omarchy without udiskie, or Arch without stub). The full decision tree
is the host unittest matrix in `tests/test_udiskie_unlock.py`. Then the
same in-guest screenshot as session-only.

`result.json` for this flow records `udiskie_unlock_cases`.

**luks-hotplug** (`--luks-hotplug PATH`): install a host Strata binary
(or archive/checkout) the same way as `vm-live --from-local`, ensure
`udiskie` is on PATH (install the package on Arch goldens), run
`strata --install-udiskie-unlock`, wrap `~/.local/bin/strata` so hook
argv is logged, format a throwaway LUKS1 image with host `cryptsetup`,
and hotplug it as `virtio-blk-pci` over QMP (`serial=strata-luks`) on a
`pcie-root-port` added only for this flow (`q35` `pcie.0` cannot hotplug).
`guest-tests/smoke-luks-hotplug.sh` waits for `lsblk` `crypto_LUKS` with
that serial, then for `--udiskie-hook` or `--unlock-volume` in the hook
log. Then the same in-guest screenshot as session-only.

`result.json` for this flow records `luks_device`, `luks_hook`, and
`luks_source`.

## vm-run (`run_test.run_vm_run`)

Same golden/overlay/host checks as `run-test`. QEMU inherits the
terminal's stdio so GTK/SDL and Ctrl-C work. Prints
`vm-run: <id> ssh_port=<port>` and waits for QEMU to exit. On clean exit
the run dir is deleted unless `--keep`; on error it is kept. There is no
"maintain" mode: the golden is never opened for writing.

## vm-live (`vm_live.run_vm_live`)

Same golden/overlay/host checks as `vm-run`. Exactly one of `--from-tag
VERSION` or `--from-local PATH` is required. Graphical GTK/SDL is the
default (`--headless` for SSH only). After SSH is up:

1. Wait for the autologin Wayland session (`smoke-session.sh`).
2. Install Strata:
   - `--from-tag`: `smoke-update.sh` previous phase downloads the GitHub
     archive for that tag and installs the binary plus desktop entry.
   - `--from-local` tarball: upload the archive and run the same previous
     phase with `UPDATE_FROM_ARCHIVE`.
   - `--from-local` binary (or a checkout containing `strata` /
     `target/release/strata`): `scp` the binary and a generated desktop
     file into `~/.local`.
3. Generate a sample tree on the host (`sample_tree.py`: documents, a
   1×1 PNG, a zip, nested dirs, a symlink, a hidden file, a name with
   spaces), upload it, and extract to `$HOME/fixtures`.
4. If `pacman` is present and `gtk4` is not, install Strata's Arch
   runtime packages (`install.sh` `REQUIRED_PACKAGES`). Tagged/local
   installs copy a binary and skip `install.sh`; the arch golden has no
   GTK, while Omarchy and GNOME guests already do.
5. Launch Strata on `$HOME/fixtures`. Hyprland 0.55+ (arch) uses
   `hyprctl dispatch 'hl.dsp.exec_cmd("…")'` — legacy
   `hyprctl dispatch exec PATH` is parsed as Lua and dies on `.local`.
   Falls back to `hl.exec_cmd` then `nohup`. GNOME uses `nohup`.

Prints `vm-live: <id> ssh_port=<port>`, the install source, and the
fixtures path, then waits for QEMU to exit. Run-dir lifetime matches
`vm-run`. Never builds a golden.

## image-prune (`overlay.prune`)

`shutil.rmtree($CACHE/runs)`; with `--images`, also `$CACHE/images`.
`$CACHE/keys` and `$CACHE/downloads` are never touched.

## Guest-side scripts

- `guest-tests/smoke-session.sh`: session selection and env export, as
  described above.
- `guest-tests/smoke-install.sh`: `install.sh` download, digest, and run.
- `guest-tests/smoke-update.sh`: seed a previous GitHub release, then run
  current `install.sh` to latest. Phases `previous` / `latest` / `all`.
- `guest-tests/smoke-about.sh`: Ctrl+, then Tab × 5 and Space to open
  About (`wtype`, or Hyprland `hyprctl sendshortcut` for the chord).
- `guest-tests/smoke-omarchy-detect.sh`: source a staged `install.sh` and
  print `DETECTED_MAJOR=` for live / token / fake-command cases
  (lgse/strata#743). Used only by `--omarchy-bindings`.
- `guest-tests/smoke-omarchy-bindings.sh`: write (optional) and assert
  Hyprland file-manager bindings for major 3 vs 4.
- `guest-tests/smoke-udiskie-unlock.sh`: source a staged `install.sh` and
  run PATH-isolated `parse_args` / `configure_udiskie_unlock` cases
  (lgse/strata#537). Used by `--udiskie-unlock` and host unittests.
- `guest-tests/smoke-luks-hotplug.sh`: wrap the installed Strata binary
  to log udiskie hook argv, wait for a `crypto_LUKS` disk with serial
  `strata-luks`, and assert Strata was called. Used by `--luks-hotplug`.
- `guest-tests/smoke-desktop.sh`: combined bus-name/hyprctl + screenshot
  oracle. Exercised by unit tests; the live `run-test` path uses the
  host-driven equivalents in `tests_spec.py` instead.
- `images/common/install-arch.sh`: earlier Arch-only installer helper.
  Superseded by `smoke-install.sh` with `SMOKE_FORBID_OMARCHY=1`; still
  exercised by unit tests.
- `images/<id>/bootstrap.sh`: host-side downloader run by `image-build`.
  Verifies the pinned SHA-256; deletes a stale cached file with the wrong
  hash. Fedora's variant scrapes the release directory listing and checks
  the `CHECKSUM` sidecar (with OpenPGP verification when Fedora keys are
  present on the host).
- `images/<id>/setup.sh`: guest-side provisioning run over SSH.

## Host tests (`tests/`)

`python -m unittest discover -s tests -t .`. The suite never spawns
`qemu-system-*`; fixtures patch `subprocess.run` / `subprocess.Popen` and
raise if a QEMU binary is invoked. Coverage includes the CLI and
`check-host` (injected env), argv builders, overlay argv, port allocation,
the shutdown cascade, QMP/qemu-ga/VNC protocol helpers over local
sockets, recipe loading and digests for every guest, seed rendering and
validation, `run-test`/`vm-run`/`vm-live` wiring with fake SSH responders, and the
guest shell smokes driven by fake `loginctl`, `busctl`, `pgrep`, `gdbus`,
`hyprctl`, `grim`, and `gnome-screenshot` on `PATH`.

## Security posture

- Guests are reachable only on `127.0.0.1` via user-mode networking; no
  bridge, no exposed VNC.
- The SSH key is a generated local fixture. `tester`/`foobar` is a
  well-known test credential and is only valid inside throwaway guests.
- Seeds are scanned for GitHub and Tailscale token patterns before being
  written; Omarchy CIDATA refuses `tailscale_authkey`, `user-data`, and
  `meta-data`.
- `install.sh` is saved to disk and hashed before execution; the digest is
  recorded in `result.json`.
- `check-host` refuses to run as root.
